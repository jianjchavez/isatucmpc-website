# PMES Quiz and Certification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a phone-friendly PMES certification quiz on the website, validated by a presenter session code, that issues numbered certificates and a per-session results sheet for Board approval.

**Architecture:** Five static Astro pages call a new `/api/pmes/*` route group in the existing Hono Worker `isatucmpc-forms`. All randomness, scoring, certificate numbering and emails live in the Worker; state lives in a D1 database `isatucmpc-pmes`. The question bank is one JSON file shared by the site and the Worker.

**Tech Stack:** Astro 6, Tailwind 4, TypeScript, Hono 4, Cloudflare D1, Workers rate limiting, Resend, Turnstile, Vitest with `@cloudflare/vitest-pool-workers`, `wrangler` 4.

**Spec:** `docs/superpowers/specs/2026-10-21-pmes-quiz-design.md`

## Global Constraints

- Pass mark 16 of 20; quiz size 20; 2 questions per section from 10 sections; max 3 attempts per identity per session; timer 20 minutes with 120 s server grace.
- Session code format `PMES-` + 4 chars from `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`; valid until 23:59:59 Asia/Manila on the session date or until closed.
- Certificate number `PMES-YYYY-NNNN`, sequential per year, from `pmes_counters` with a single `UPDATE … RETURNING`.
- Organization name only as the letterhead strings in the `isatucmpc-letterhead` skill; invoke that skill before writing any certificate or results-sheet template; grep output for `consumers|& multi|multi purpose` before commit.
- pnpm v11: install with `--ignore-workspace --ignore-scripts`; run tools via `./node_modules/.bin/`. Worker commands run in `worker/`.
- `docs/ARCHITECTURE.md` updated in the same PR; bump "Last verified".
- Shared checkout: verify `git branch --show-current` is `feat/pmes-quiz` before every commit.
- Task tags: `mechanical` / `coding` / `critical` per the /auto routing table.

## Review Focus

1. Same person retaking after a pass: `start` must return `already-passed`, never a fourth draw. (Task 6)
2. Submit at 20:01 with the 120 s grace, and at 22:30 past grace: the first scores, the second stores score 0 with status `expired` and still counts as an attempt. (Task 7)
3. Two attendees pass in the same second: certificate numbers must be distinct and consecutive; no duplicate `seq`. (Task 8)
4. Session created at 23:50 Manila: code valid for ten minutes only; `code-expired` after midnight Manila even though UTC date differs. (Task 4)
5. Resend outage during submit: the attendee still gets their result and certificate on the page; `email_status` is `failed` and the roster shows it. (Task 9)
